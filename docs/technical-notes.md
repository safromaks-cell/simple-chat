# Технические заметки: Simple Chat

Подробности исходной Windows-установки и предыдущих проверок. Пути и измерения ниже относятся к той установке; основные инструкции находятся в [README](../README.md).

# Простой чат Qwen

Двойной щелчок по `Start Chat.cmd` открывает http://127.0.0.1:8791.

Лаунчер запускает отдельный скрытый процесс `run-chat.cjs`: он сохраняет уже работающий сервер и активный ответ, а при остановке сервера запускает его повторно через несколько секунд. Сайт не зависит от открытой вкладки браузера или рабочей сессии Codex. Повторный запуск лаунчера не создаёт второй контроллер. Вывод новых запусков сервера сохраняется в `server.log` и `server-error.log`. Автозапуск при входе в Windows не добавляется.

Модель: `jaahas/qwen3.5-uncensored:9b` (Ollama, Q6_K, около 7.4 ГБ).
Источник: https://ollama.com/jaahas/qwen3.5-uncensored:9b

Открытие страницы не загружает модель: она загружается по кнопке «Загрузить на GPU» или при отправке сообщения. Аргумент `--web-only` при запуске `run-chat.cjs` также блокирует фоновую автозагрузку из старых вкладок. Прогресс виден в чате. Ollama используется как загрузчик своей библиотеки. Вычисление выполняет отдельная копия llama.cpp CUDA из `runtime/`. Сервер доступен на этом компьютере и в локальной сети. Нужны установленные Ollama и Node.js (лаунчер также находит встроенный Node из Codex).

Есть потоковые ответы, остановка генерации и список сохранённых диалогов. «Новый чат» создаёт отдельный диалог; предыдущие остаются в списке. Сообщения автоматически сохраняются в `data/chats.json`, включая частичные ответы раз в две секунды. Старые браузерные истории автоматически переносятся при первом открытии. Системный промпт редактируется в «Настройки · системный промпт», сохраняется отдельно для каждой модели в `data/settings.json` и передаётся как сообщение роли `system`. Пример роли киберспециалиста и учёного также сохранён в `System Prompt.txt`. Enter отправляет сообщение, Shift+Enter переносит строку. Рабочий контекст выбирается отдельно для модели: 32768 токенов для Qwen 9B, Cyber-Ornith и Gemma 12B, 16384 для Qwen 27B и CyberStag; профили находятся в `context-profiles.json`. Используется KV-кеш q8_0 (сжатие кеша без изменения файлов весов). Если формат кеша не поддерживается, используется f16 с меньшим контекстом; при ошибке выделения памяти лимит уменьшается до 4096. Полные паспортные 131–262 тысячи токенов не включаются автоматически на видеокарте 8 ГБ. Фиксированный лимит длины ответа снят (`max_tokens: -1`): генерация идёт до завершения ответа моделью или нажатия «Стоп». Общий контекст остаётся техническим пределом движка.

История считается реальным токенизатором загруженной модели, с учётом шаблона чата и запаса под ответ. Запас не ограничивает длину генерации и уменьшается для длинного одиночного сообщения, если оно помещается в общий контекст. При заполнении примерно 80% доступного входного бюджета старая история автоматически сжимается самой моделью в сводку. Последние реплики сохраняются целиком; если они сами не помещаются, сжимаются более ранние из них, последняя реплика пользователя всегда сохраняется полностью. Сводка хранится в `data/context-memory.json`, отдельно для каждого чата и модели; изменение ранее сжатых сообщений сбрасывает её. Полная переписка остаётся в `data/chats.json` и в интерфейсе. Сжатие требует отдельной генерации и может опустить детали. Слишком большое одиночное сообщение вызывает понятную ошибку, а не молча обрезается. В интерфейсе видны лимит, число использованных токенов и число сообщений в сводке.

Над полем сообщения отображается скорость генерации в токенах в секунду: скользящее окно за последние пять секунд, обновление каждые полсекунды. После ответа остаётся средняя скорость без ожидания первого токена. Знак «≈» означает оценку по событиям потока, когда движок не передаёт точные счётчики токенов.

В верхнем поле можно вставить ссылку на публичный или доступный вашему токену репозиторий Hugging Face с GGUF либо ссылку Ollama. Загрузки идут по очереди. Для HF автоматически выбирается Q4_K_M, затем IQ4_XS или другой доступный подходящий вариант. Можно вставить ссылку на конкретный GGUF для точного выбора квантизации. Поддерживаются разделённые GGUF; imatrix, mmproj, adapters и safetensors не выдаются за готовые чат-модели. Совместимость конкретной архитектуры зависит от llama.cpp: успешное скачивание не гарантирует запуск. SHA-256 проверяется по метаданным Hugging Face. Незаконченные HF-загрузки продолжаются после перезапуска.

Скачанные модели выбираются в списке. При переключении предыдущий процесс GPU выгружается, затем загружается новая модель. Запросы сериализуются. Автоматическое уменьшение количества GPU-слоёв отключено (`--n-gpu-layers all --fit off`); чат проверяет сообщение движка о загрузке всех слоёв на GPU. CPU inference fallback отсутствует. CPU обслуживает интерфейс, загрузку файлов, токенизацию и управление CUDA.

На Windows перенос страниц весов между системной памятью и GPU зависит от NVIDIA System Memory Fallback. Это механизм драйвера, а не собственный планировщик слоёв или гарантированное постоянное хранение всех скачанных моделей в RAM. Если CUDA не может выделить память, будет показана ошибка без запуска на CPU. Большие модели могут работать медленно из-за передачи через PCIe. Настройки драйвера и другие запущенные программы автоматически не изменяются.

HF-токен хранится в `credentials/hf-token.dpapi`, зашифрованный Windows DPAPI для текущего пользователя. Токен используется только для HTTPS-запросов к Hugging Face и не отдаётся браузеру. Сырые данные credentials, data, models и runtime исключены из Git через `.gitignore`.

## Доступ в локальной сети

Открой на телефоне или другом устройстве `http://192.168.0.138:8791` (актуальные адреса также видны в «Доступ в сети»). Пароль не нужен по настройке владельца. Диалоги и сохранённые промпты общие для устройств. Компьютер должен оставаться включённым. Если Windows блокирует входящие подключения, один раз запусти `Enable Network.cmd` и подтверди запрос UAC. Скрипт добавляет правило только для TCP 8791 и устройств локальной подсети, не отключая брандмауэр.
